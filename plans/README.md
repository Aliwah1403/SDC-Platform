# Animation plans — Hemo mobile

Generated by `improve-animations plan` from a `find-animation-opportunities` sweep of
`apps/mobile/`. All plans stamped against commit **d6c2795** (branch `dev-branch`).

These are **additive** plans — every one is a missed opportunity (AUDIT.md category 8),
not a correction of broken motion. The app's existing animation is largely right:
`apps/mobile/src/utils/motion.js` is a real token file, `PressableScale` is a real
shared primitive, and onboarding, auth, log-symptoms, track and care/index are already
animated well. The gaps are concentrated in surfaces built later — care/medications,
rewards, community — that never got the same pass.

## Recommended execution order

**001 → 003 → 002 → 005 → 004 → 006**

Rationale:

- **001 first.** Highest leverage by a distance. Medication adherence is the app's core
  daily loop and the only place a user earns feedback every single day; right now the
  reward is a rectangle that jumps. It is also the only plan where the missing motion
  costs *legibility* rather than just polish.
- **003 second.** It is the one plan with a genuinely corrective element (two collapses
  in `crisis-mode.jsx` animate in but not out), it touches three files, and it has a
  perfect in-repo exemplar to copy from at `metric-detail.jsx:727-748`.
- **002, 005** next — self-contained single files, no coordination needed. 005 is the
  cheapest win in the set: one file, seven screens improved.
- **004, 006** last. Pure polish on low-traffic (004) or deliberately-restrained (006)
  surfaces.

## Dependencies

None of the six are blocking on each other. They can be executed in parallel or in any
order. Two coordination notes:

- **001 and 002 both animate a progress fill and deliberately use different
  techniques.** 001 animates `width` (its fill has `borderRadius: 3`, which `scaleX`
  would visibly distort on a 6px-tall bar); 002 uses `scaleX` with
  `transformOrigin: "left"` (its fill has no radius of its own and is clipped by the
  parent). Each plan states this. **Do not "harmonize" them** — an executor that makes
  them match will regress one of the two.
- **002 and 006 both touch the community feed.** `PostCard.jsx` renders `PollBlock.jsx`
  but neither plan edits the other's file, so there is no conflict. If running both in
  one worktree, expect a clean merge.

## Shared conventions every plan relies on

- **Tokens**: `apps/mobile/src/utils/motion.js` — `pressSpring`, `enterTiming` (220ms),
  `exitTiming` (150ms), `celebrationSpring`, `STAGGER_MS` (40),
  `easeOutStrong` (`cubic-bezier(0.23, 1, 0.32, 1)`),
  `easeInOutStrong` (`cubic-bezier(0.77, 0, 0.175, 1)`).
  No plan introduces a new token; 006 deliberately keeps its one-off springs local.
- **Press feedback**: `apps/mobile/src/components/PressableScale.jsx`.
- **Reduced motion**: `apps/mobile/src/hooks/useReducedMotion.js`. Every plan gates its
  motion on it, reducing to opacity-only — never to zero. Exemplar:
  `apps/mobile/src/app/(tabs)/care/index.jsx:49`.
- **Libraries**: Moti 0.30 + Reanimated 4.5 are already installed. **No plan adds a
  dependency.**

## Explicitly rejected — do not "fix" these

These were considered during the sweep and deliberately left alone. If an executor
reports them as findings, the answer is no:

- `(tabs)/_layout.jsx:37-71` — tab bar icon/label transitions. Core navigation, 100+

- `Insights/patternRows.jsx:64` — the `MiniBars` trigger-frequency bars. This is

### Correction: the mechanical checks in plans 002–006 are wrong

Plans 002–006 each say to run `npx jest` (and 001 originally said `npx tsc --noEmit`).
Executing 001 established that **neither tool gives any signal on this codebase**:

- **There are no tests.** `npx jest` in `apps/mobile/` reports "No tests found" —
  441 files checked, 0 matches — even though `CLAUDE.md` documents it as the test
  command.
- **`.jsx` files are never typechecked.** `apps/mobile/tsconfig.json` `include` is only
  `**/*.ts` / `**/*.tsx`. Every file targeted by these six plans is `.jsx`. The repo
  has 12 pre-existing `tsc` errors, all in unrelated `.ts`/`.tsx` files.

Substitute this parse check, adjusting the path per plan:

```bash
cd apps/mobile && node -e "
const babel=require('@babel/core'),fs=require('fs');
const f='src/app/(tabs)/care/medications.jsx';
babel.parseSync(fs.readFileSync(f,'utf8'),{filename:f,presets:['babel-preset-expo']});
console.log('PARSE OK');"
```

It catches syntax and unbalanced JSX and nothing else.

### Everything real is a device check

**Every plan's feel check requires a real device or simulator**, and with no tests and
no typechecking on `.jsx`, that is the *only* meaningful verification these changes
get. Plans 001, 004 and 006 each name a specific regression that no static check will
catch — 001's (a nested `Pressable` swallowing or leaking the row's `onPress`) was
found only by reasoning about the diff, not by any tool.
